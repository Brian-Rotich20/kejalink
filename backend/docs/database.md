# KejaLink: Database

PostgreSQL with Drizzle ORM. Schema source: `src/db/schema/*`. Migrations: `src/db/migrations` (generated by drizzle-kit and checked in; `0002` was hand-edited, see below).

## Tables

```text
user ─┬─< session         (ON DELETE CASCADE)
      ├─< account         (ON DELETE CASCADE; holds the password hash)
      ├─< properties      (tenant_id, ON DELETE RESTRICT)
      │      ├─< uploads  (ON DELETE CASCADE)
      │      └─< bookings (property_id, ON DELETE RESTRICT)
      └─< bookings        (seeker_id, ON DELETE RESTRICT)
verification (Better Auth; unused in V1 because verification is off)
```

All timestamps are `timestamptz`. Users are never hard-deleted: deleting them is disabled, and `RESTRICT` foreign keys protect their properties and bookings.

### `user` (Better Auth + app fields)

| Column | Type | Notes |
|---|---|---|
| id | text PK | Better Auth id (not a UUID) |
| name | text | 1–100 characters, enforced at sign-up and in `PATCH /users/me` |
| email | text UNIQUE | |
| email_verified | boolean | always false in V1 |
| image | text null | https URL |
| role | text NOT NULL default `SEEKER` | CHECK `user_role_check`: `TENANT`, `SEEKER` or `ADMIN` |
| status | text NOT NULL default `ACTIVE` | CHECK `user_status_check`: `ACTIVE`, `SUSPENDED` or `BANNED` |
| created_at, updated_at | timestamptz | |

`session`, `account` and `verification` are Better Auth's standard tables (indexes `session_userId_idx`, `account_userId_idx`, `verification_identifier_idx`, unique `session_token_unique`).

### `uploads`

`id uuid PK`, `property_id FK`, `cloudinary_public_id varchar(255) UNIQUE` (never returned to clients), `url`, `is_primary`, `display_order smallint`, `created_at`. At most 10 rows per property, enforced under the property row lock.

### `bookings`

`id uuid PK`, `property_id FK`, `seeker_id FK`, `status` enum `booking_status` (`PENDING`, `CONFIRMED`, `REJECTED`, `CANCELLED`; default PENDING), `preferred_move_in_date date null`, `message`, `decision_reason`, `decided_at`, `created_at`, `updated_at`.

## Integrity rules enforced by the database

| Rule | Mechanism |
|---|---|
| Unique email | `user_email_unique` |
| Valid role and status, never NULL | `user_role_check`, `user_status_check`, NOT NULL |
| One PENDING request per seeker and property | partial unique `bookings_one_pending_per_seeker_property_idx (property_id, seeker_id) WHERE status = 'PENDING'` |
| One CONFIRMED booking per property | partial unique `bookings_one_confirmed_per_property_idx (property_id) WHERE status = 'CONFIRMED'` |
| One primary image per property | partial unique `uploads_one_primary_per_property_idx (property_id) WHERE is_primary` |
| Unique Cloudinary asset | `uploads_cloudinary_public_id_unique` |
| Positive price, non-negative rooms | CHECK constraints on `properties` |

The app maps unique violations to domain errors (`DUPLICATE_BOOKING`, `PROPERTY_NOT_AVAILABLE`), and any other `23505` to 409 `CONFLICT`.

## Indexes for the actual queries

| Query | Index |
|---|---|
| Discovery filters (county/type/price) over live listings | `properties_discovery_idx (county, property_type, price_amount) WHERE status='PUBLISHED' AND deleted_at IS NULL` |
| Discovery default sort (newest) | `properties_newest_idx (created_at DESC, id DESC) WHERE status='PUBLISHED' AND deleted_at IS NULL` |
| Tenant's listings, `/received` join | `properties_tenant_id_idx` |
| Seeker's bookings | `bookings_seeker_id_idx` |
| Bookings of a property (confirm, delete, lists) | `bookings_property_id_idx` |
| Images of a property | `uploads_property_id_idx` |

## Concurrency

The global lock order is the **property row first, then booking rows**:

| Operation | Locks |
|---|---|
| Create booking | `SELECT … FOR SHARE` on the property |
| Confirm / reject / cancel | read `bookings.property_id` (no lock), lock the property `FOR UPDATE`, then the booking `FOR UPDATE` |
| Property update/delete, admin reject/restore/delete, upload insert/update/delete | the property `FOR UPDATE` |

The connection pool sets `statement_timeout = 10s` and `idle_in_transaction_session_timeout = 15s`.

## Time

- `timestamptz` everywhere. Production runs with `TZ=UTC`.
- `preferred_move_in_date` is a `date` (a calendar day). "Not in the past" is checked against today's date in **Africa/Nairobi**.

Workflow:
1. Edit `src/db/schema`.
2. Run `npm run db:generate`, review the SQL, and commit it.
3. Apply with `npm run db:migrate` (dev and CI) or `node dist/scripts/migrate.js` (production image).

Never use `drizzle-kit push`. `npm run auth:generate` writes to `.drizzle/auth.generated.ts`; merge any changes into `schema/auth.ts` by hand.
